- Pools: implicit pool semantics for plain offers (capacity = offer capacity, one unit per slot-second); close allowed when no reserved/active commitment; a cancel after activation truncates at the release point.
- Custody: `history.CATEGORIES` lacked `native.signing`; the capability refusal is 501 not 503; `await_signature` must rank below settlement/decision but above `wait`; the settlement context lacked `payment_intent`; an intent left `submitted` on a missing signature (now `native_signature_required` is raised before exposure and `settlement_preview` exists); the await result landed in `_validate` instead of `_perform`; several settlements of one milestone shared a nonce (first: consecutive nonces in the controller; final: **sequence numbers allocate at preparation**, see below); a reservation context hashed with extra keys (bound context separated from `extra`); the reservation interval drifted between prepare and submit (pinned).
- **Sequence numbers** (found by the demonstration in full run 2): a signed-but-unsubmitted intent (the losing side of a race, a voided request) made the signer refuse the account's next intent (`sequence`), because the service reused the counter until submission. Fixed: prepare / reservation-prepare / settlement requests consume a sequence; submission accepts any allocated unused sequence (`nonce_replayed`, `nonce_stale`); unit test added.
- Sub-contracts: freezing the child as the requester (now at creation); compartments route path; a **failed child left the primary's reservation locked** (found by the demonstration): a rejected milestone now closes its award and releases the unspent reservation (`award_closed`).
- Lots: 19-value allocation inserts after the ALTER; `validate_message` rejected boolean `partial`; a transfer double-counted lots (now an ownership change); the return route ignored `amount`; `partially_returned` missing from state maps; the **accounting view ignored partially returned backing and pending partial retirements** and the lineage row kept retired units (found by the endurance smoke); legacy consumed imports without lots are reported `legacy_without_lineage` instead of failing the partition check (found by the base-revision migration rehearsal).
- Provider client verifier: the lot rule assumed children exclude the parent; the implementation splits in place (fixture and verifier aligned; vectors v2 regenerated).
- Products: `source` is an embedded descriptor; floats refused (integer mm/px). Relay: KiB floor in expectations; validation order. Continuity: pause stop reason. Portfolio: admitted order; the planner was not pool-aware so the validator refused its own plan (pool-aware planner with a shared scheduling rule).
- Onboarding: the identity route called the wrong object (`Board` instead of `Providers`).
- Harness: journey ordering dependencies (shared actors created at setup), signer ceilings for cpu-ms priced reservations (race moved to a contact pool), reconcile needs observations from every pinned peer (three domains), a 300 s wait on an already-opened request (journey 40), balance checks that ignored earlier reservations, deltas measured after later steps, tuple/list comparisons, the demonstration's sub-contract had to be created while the parent milestone was executing, the examples builder used a wrong CLI flag and skipped provider registration.
- Endurance: offer capacity above the pool's yield; final checks over a non-quiescent state (now flushed before checking).

## Endurance defects (runs 2 and 3 at 53c9d49; found and fixed 2026-10-23 by the recovery session)
- **Masked lock-wait timeout** (6 unexpected in run 2: 4 pool reservations, 2 signed transfers; 4 in run 3): `Database.tx()` issued `ROLLBACK` after `BEGIN IMMEDIATE` had failed with `database is locked` (15 s busy timeout); the second error ("cannot rollback - no transaction is active") replaced the first, so a retryable `JOURNAL_BUSY` (503) was reported as `LOCAL_OPERATION_FAILED` (409) with no detail, and the private defect log (last 4000 characters of the chained traceback) had lost the original line. Reproduced deterministically; `tx()` now rolls back only an open transaction and re-raises the original error; `JOURNAL_BUSY` carries `Retry-After: 1` and `{retryable, begun:false}`; busy events go to `logs/busy.log`; the defect header names the chained cause. The event log of run 3 shows commits every second through the failure windows (no quiet gap ≥ 4 s, witness acknowledgments ≤ 1 s, worker ticks ≤ 6 ms, commit ≈ 5 ms): no single long holder — the timeouts were starvation of long waiters by SQLite's polling busy handler under saturation bursts (~40 API threads + 2 workers). An in-process fair write gate now queues a process's transactions ahead of the busy handler.
- **Worker exit on a busy database** (run 3: both `end-a` workers offline at 783 s and 787 s, 7 jobs queued for up to 1155 s, 5 `execution_incomplete` and one harness `KeyError` on a 503 award view): one `database is locked` on the claim/heartbeat propagated out of `run_forever`. The worker loop now logs the timeout, pauses and continues (gives up after 120 consecutive timeouts); the result publication retries up to five times so a computed job is never lost to a timeout.
- `api.py` never imported `os`, so `os.chmod(defects.log, 0o600)` raised inside its `except Exception: pass` and the defect log stayed group/world-readable (0644 observed); fixed.
- Endurance harness: `JOURNAL_BUSY` is retried with the identical call (same request id) and the retry's outcome is counted; an exhausted retry budget is unexpected; `ok` additionally requires every worker alive at the end, backlog age ≤ 300 s and zero exhausted retries. Regression coverage: `tests/test_db_contention.py`.
- **Write gate cost** (found by the before/after benchmark at 2ff4da5): the first gate (ticket lock with `notify_all`) cut the 300-transfer / 8-client native benchmark from 88.5/s (gate off, same tree) to 56.2/s and multiplied p50 by seven — every release woke every waiter, and connection set-up ran inside the serialized section. Replaced by a hand-off FIFO (release gives ownership to the oldest waiter and wakes only that thread; connections open and close outside the gate): 93.5/s, p50 0.084 s, p95 0.096 s against 88.5/s, p50 0.019 s, p95 0.25 s ungated — same throughput, no barging, tighter tail. Measured with `METACOIN_DB_WRITE_GATE=0` vs `1` on the same tree (scratch runs; the recorded `benchmark-native-after.json` is the final tree).
- **Cross-process starvation by the hand-off gate** (endurance run 5 at 63a036e, `endurance-network-run5-63a036e.json`): the API process's seamless hand-off chain never left the file lock free long enough for the worker processes' SQLite busy-handler polls (back-off up to 100 ms) to land: 90 worker lock-wait timeouts (survived, as designed), only 52 work-loop completions (run 4: 211), work p99 157 s, 107 jobs executed (run 4: 422) — conserved and "ok" by the harness criteria of the time, which is why the acceptance now also bounds service busy events (≤ 10) and work p99 (≤ 90 s). Fix: `BEGIN IMMEDIATE` is retried at a fixed 1 ms interval in every process (SQLite's own busy timeout stays for other statements) and a thread that received the gate by hand-off yields 0.5 ms before BEGIN, so another process's poll can win. Regression test: a separate process behind a saturating 8-thread process completes hundreds of transactions with zero timeouts. Throughput: 88.2 transfers/s (ungated 88.5), p95 0.105 s.
