# Defects found and fixed during Order 08 (each with its coverage)

1. **Terms freeze crashed on the reviewer lookup** (`sqlite3.Row` has no `.get`): fixed; covered by test_work_terms.
2. **energy_audit `full_exact` verification took the generic audit path** and failed on a missing `result` field: verification.compute_audit now runs the WorkContract v0 full private audit for that kind; covered by test_work_terms (positive/negative both verified) and journeys 8–9.
3. **Legacy task replay refused by the Merkle vault** (floats in the canonical result): the canonical result travels as a JSON string; covered by test_work_terms fixtures and journey 11.
4. **Provider role could not be created**: the principals table carried a CHECK on the role set; migration 033 rebuilds the table with foreign keys off and verifies integrity; covered by test_work_board and the migration tests.
5. **Earliest-offer tie-break was non-deterministic within one second** (created_at resolution): insertion order (rowid) is the key; covered by test_work_board.
6. **Milestone dependency gating overwrote a policy cancellation** with the generic blocked reason; fixed; covered by test_work_evidence (three milestones).
7. **Refund identifier too short for the SDK payment-identifier rule** (16–128 chars): stable sha-derived identifier per request key; covered by test_work_money.
8. **Lost-response modelling**: the SDK resource server reconciles a receipt-wait timeout internally, so an application-level lost response is modelled by dropping the observation after execution; covered by test_work_money and journey 33.
9. **Distinct-verifier semantics**: a same-worker execution audited by the same service was counted as distinct because the auditor id differed from the provider principal; the rule now keys on execution custody (node execution = separate process); covered by test_work_evidence.
10. **Worker crashed when a job's input artifact had been deleted after dispatch**: the attempt now fails INPUT_INVALID and the loop continues; covered by test_work_access_missions and journey 24.
11. **Refused audit accesses were rolled back with the refusal** (no access event recorded): events are persisted before the refusal; covered by test_work_access_missions.
12. **Journal deduplicated a second submission attempt** (same event key after a reconciled-unused first submission), leaving exposure negative: submission events are per attempt; found by the fault campaign (test_work_faults), which also checks the independent model.
13. **Journey harness could not start its API**: METACOIN_LIMITS_JSON refused `job_max_retries=0` and the unknown `test_hooks` key; config gains `test_hooks` (default 0) and the harness uses one retry with two timed-out attempts.
14. **Test expectations updated for legitimate changes**: installed services now include `legacy_task_replay` (catalog and prior-backup tests); the older-backup restore fixture became generic over later migrations.
15. **Entitlement insert missed the new `kind` column** after fee/verifier entitlements were added; fixed; covered by test_work_money.
16. **Exposure reversal posted for never-submitted expired intents**: reconciliation posts a reversal only when a submission carried exposure; covered by test_work_money (expiry flow) and journal replay.
17. Journey harness helper `api()` collided with the base harness's `self.api` Popen attribute ("'Popen' object is not callable"); renamed to `call()`. Every journey failed until fixed (run 3).
18. Single-shot workers claim the oldest queued job, so journeys that leave jobs queued on purpose (2–6, 25–28) starved later journeys ("target job has no committed result"); `run_workers` now drains the queue and journey 29 / the browser run drain before their own contracts.
19. Journeys 11 and 29 read `/api/v1/compute/jobs/{id}` for non-compute jobs (NOT_FOUND "not a compute job"); the generic `/api/v1/jobs/{id}` view is used.
20. Numerical witness (resource_plan): the job-level outcome is the checker verdict (VERIFIED) while the solver status lives in the summary; `science_conclusion` and the `status_in` predicate now read the summary status, and the infeasibility_witness template treats FEASIBLE / INFEASIBLE / INDETERMINATE explicitly (its earlier `not_applicable` treatment made every witness unpayable).
21. Agent grants had no work operation, so an MCP agent could compare offers but never award (403 work:award); `work:read` and `work:award` are grant operations now and the award guard is keyed on `work:award` with the offer amount against the grant ceiling.
22. A provider whose registered payout address is not a chain address could be awarded a local-chain-token contract; the payer signing then failed inside the x402 SDK (`Invalid address length`) and surfaced as INTERNAL_DEFECT without any trace. Eligibility now refuses with `recipient_invalid_for_rail`, and the API writes unexpected exceptions to a private `logs/defects.log` (0600, no bodies or headers).
23. Sampled-verification statement claim reads "challenge-selected scenarios recomputed … compared exactly"; journey 16 accepted only the word "sampled" — the check now accepts either wording (the receipt separately labels sampling as a distinct class).
24. Browser journey waited for the word "INFEASIBLE", which the frozen-terms JSON on the award page always contains, so the check raced the worker; it now waits for the milestone row's execution badge and science cell. The list-based diagnostics added to the browser hook (queue state, worker liveness, last award) stay in the harness.
25. Journal replay guessed the network scope of an accepted-but-unpaid chain entitlement as `local-chain` while the acceptance posting used the chain identity (`eip155:…`); found by the §66 demonstration (an accepted decision created through a dispute stays payable with no intent). The replay now takes the scope from the milestone's own acceptance posting; nothing in the journal changed.
26. Fee entitlements (kind `fee`) were not listed on the award view (only reachable by id or the console page); the award view now lists every entitlement with its kind so a client can pay the fee it agreed to without a database read.
27. Numerical-witness template declared `valid_negative.requires = [verification_passed, status_in]` in a first fix attempt; `status_in` is not a valid requirement type (validation rejected every witness contract); corrected to `source_revision`.
28. Program runs with a ceiling below the class payment rule were refused at freeze (`payment_rule_exceeds_ceiling`); a run now bounds every payment class and milestone maximum by its own ceiling.
29. Strict JSON forbids floats: the pricing experiment takes `metered_bps` (integer basis points), and the catalog price identity is hashed from a sorted JSON dump rather than the float-free canonical form.
30. A provider or reviewer has no contract authority; a challenge's counterexample job is created by the service on the challenger's behalf (attributed to the challenger, bounded to 4 open challenges and 32 KiB of inputs) with the workspace reviewer as the contract reviewer.
