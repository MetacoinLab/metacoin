# Innovation record — Step 01 hardening session, 2026-09-23

One row per implemented improvement. "Baseline" is the 2026-09-18 handoff
(commit 5d988bd on this branch). Observations are from this session's runs on
Linux 6.17 aarch64 / Python 3.12.3; nothing external was involved.

| Problem (baseline) | Change | Hypothesis | Baseline behavior | Test | Observation | Limitation |
|---|---|---|---|---|---|---|
| Any upgrade of the audited source made every earlier contract and receipt unverifiable: `validate` demanded the installed digest | `verifiers.py` allowlist; `validate(mode)`; `verify_public` accepts historical bundles read-only | Old public receipts stay verifiable; nothing new can be authorized under an old bundle | The handoff's own public demo output failed `verify_public` after any edit to acceptance.py | `test_hardening.VerifierEvolutionTests` using the handoff's real v0 output as a fixture | 3/3 historical receipts verify with status `historical`; register/execute/request refuse with `VERIFIER_SUPERSEDED`; unknown digests refuse | The allowlist is local policy edited by a human; it does not authenticate who produced a receipt |
| No explanation of where indeterminacy comes from; auditor saw only margins | `explanation.py`: exact decomposition of margin width into the battery-bound term and per-segment terms, ranked; counterfactual shift; threshold check | Auditor can name the dominant declared uncertainty without exposing inputs publicly | Only `worst_margin`, `best_margin`, `additional_usable_energy` | `test_explanation.py` (200 seeded cases against a Fraction watt-hour reference, zero width, boundary, split invariance, tie order, privacy) | Sum of contributions equals width in all cases; threshold minimality verified on 103 inputs; explanation absent from public bundles unless the policy lists it; cost 0.024 ms median | An exact interval-width split, not a probability or an information-gain estimate; correlations and model error are outside the model |
| Private audit held the journal's write lock (`BEGIN IMMEDIATE`) for its whole duration | Audit computed outside the lock, bound to a registration snapshot, rechecked atomically before recording | Unrelated reservations are not blocked; no TOCTOU window opens | A concurrent `BEGIN IMMEDIATE` during an audit raised "database is locked" | `test_private_audit_does_not_hold_the_write_lock`, `test_audit_recheck_refuses_when_another_root_was_recorded_meanwhile` | Lock is free during recomputation; a racing audit that records another root first makes the slower one refuse (`EVIDENCE_IMMUTABLE`) | Bounded model audits take ~1.4 ms, so the practical gain here is for larger future tasks |
| An identical retry after `expires_at` was refused, hiding an already recorded outcome | Expiry gates new reservations only; existing identical actions return their state | Operators can read outcomes after expiry without a new right being created | `dispatch` raised "spend authorization refused" for a CONFIRMED action once expired | `test_identical_retry_after_expiry_returns_recorded_state_without_new_right` | Retry returns CONFIRMED with one adapter call in total; a fresh request after expiry refuses with `EXPIRED` | – |
| Adapter answers were checked for shape and digest only | Semantic consistency: units must match the bound amount for CONFIRMED; FAILED grants 0; answers for never-claimed rows are unbound | A wrong-but-well-formed answer cannot confirm or free budget | An answer with `compute_units: 999` would have been recorded as CONFIRMED | `test_semantically_inconsistent_answers_preserve_uncertainty`, `test_duplicate_and_conflicting_answers_in_any_order` | Both inconsistent shapes leave `OUTCOME_UNKNOWN` with exposure retained; conflicting terminal answers are refused | Consistency is only as strong as the adapter's declared `expected_units`; a real rail must declare its own |
| Interruptions were injected in-process only | Child-process harness with `os._exit` at six exact points, two provider kinds, cross-process races | Restart invariants hold under real process loss | Three in-process patch points | `test_interruption.py` (6 tests, 20+ child processes) | All six points recover as tabulated in `ACCEPTANCE_MATRIX_STEP_01.md` §4; six concurrent processes produce one dispatch; budget and entitlement races resolve to exactly one confirmation | Not power loss; the durable provider is a test double whose guarantees a real rail must be checked against |
| Every CLI failure printed one identical sentence | `refusals.py` codes with operator actions; coverage test over every raise site | Operators can distinguish invalid input, wrong version, exhausted budget, expiry, and unavailable reconciliation without seeing private data | `REFUSED: invalid input, authorization, evidence, or local operation.` for everything | `RefusalCodeTests`, `test_cli.test_refusal_paths_redact…` | 40 codes; every refusal message is a string literal; canary and temp path absent from stdout/stderr on six failure paths | Journal-side codes such as `WORK_NOT_ACCEPTED` are visible to the local operator and imply the policy result; public verification never sees them |
| Operational steps beyond the scripted demo needed Python edits | Journal-backed and package CLI commands; dry run; verbatim walkthrough | A pilot can be run without editing source | Only fixture/prepare/execute/audit/verify/demo | `test_walkthrough.py` (runs `pilot/walkthrough.sh`), `test_cli.py` | 17 steps run verbatim in ~1 s of compute with 2 manual copy steps | The legacy adapter remains process-scoped; the durable adapter is a test facility |
| No constrained way to hand a reviewer or an auditor the right files | `packages.py` public/private zip packages with whitelist, manifest, size bounds | Round trip works; malformed or private-bearing packages are refused before extraction | Files were copied by hand | `test_packages.py` (11 tests) | Missing, substituted, extra, duplicate, traversal, absolute, symlink, oversize, version and private-marker cases all refused with nothing extracted | The manifest authenticates nothing about the publisher |
